# AgentCyTE 贯通指导使用说明

> 完整链路实测验证版：**XML → AgentCyTE(CLI/Web) → CORE daemon(gRPC) → core-http-bridge(HTTP 双入口确认)**。
> 环境：AgentCyTE 离线包 venv 版（内置 vendor/core 9.2.1），宿主 core-daemon(127.0.0.1:50051)，core-http-bridge(8080)。

---

## 0. 部署形态速览

```
┌────────────────────┐   XML 文件    ┌──────────────────────┐   gRPC    ┌─────────────────┐   HTTP    ┌──────────────────┐
│ 编写/编辑场景 XML    │ ──────────▶ │ AgentCyTE            │ ────────▶ │ CORE daemon     │ ────────▶ │ core-http-bridge │
│ (Node Info/Routing/ │  上传/读取   │ (.venv, 内置 vendor/ │  50051    │ (宿主, 建会话)   │   8080    │ (查/删会话/节点)  │
│  Services 等 section)│             │  core 客户端)        │           │                 │           │                  │
└────────────────────┘             └──────────────────────┘           └─────────────────┘           └──────────────────┘
```

- 角色解析、路由规划在 XML section 里声明，AgentCyTE 负责解析并 gRPC 推给 core。
- core-daemon 真正创建会话；core-http-bridge 提供 HTTP 视角查看/删除该会话（与宿主持有状态一致）。

---

## 1. XML 场景文件构造（关键：section 名必须匹配 AgentCyTE 解析器）

AgentCyTE 按**固定 section 名**解析 XML，写错名字就静默 fallback（节点变默认 10 台 Workstation、路由器不生效）。

### 最小可用模板

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Scenarios>
  <Scenario name="my-scenario" scenario_total_nodes="6" base_nodes="6">
    <ScenarioEditor>
      <BaseScenario filepath=""/>

      <!-- 1) Node Information: 声明参与节点角色 + 数量 -->
      <section name="Node Information" base_nodes="6" density_count="6">
        <item selected="Router"     v_metric="Count" v_count="2"/>
        <item selected="Workstation" v_metric="Count" v_count="4"/>
      </section>

      <!-- 2) Routing: 声明路由协议 + 路由器数量（有它才建“真路由器”带服务） -->
      <section name="Routing" density="1.0">
        <item selected="OSPFv2" v_metric="Count" v_count="2" r2s_mode="Exact" r2s_edges="2"/>
      </section>

      <!-- 3) Services(可选): 给主机分配服务; 不写则路由服务也由 Routing 决定 -->
      <section name="Services" density="1.0">
        <item selected="SSH" v_metric="Count" v_count="4"/>   <!-- 4 台主机都带 SSH -->
      </section>

      <section name="Notes"><notes>说明文字</notes></section>
    </ScenarioEditor>
  </Scenario>
</Scenarios>
```

### section 语义速查（实测核实）

| section | 作用 | 关键字段 | 说错/缺省的后果 |
|:--|:--|:--|:--|
| `Node Information` | 定义角色与数量 | `<item selected="Router" v_metric="Count" v_count="2">`；`base_nodes`/`density_count` 控总节点数 | 缺 → 默认 10 Workstation |
| `Routing` | **关键**：声明路由协议与路由器数 | `<item selected="OSPFv2" v_metric="Count" v_count="2" r2s_mode="Exact">` | 缺 → router 成普通 PC 节点（无 zebra/OSPF），拓扑走扁平 star |
| `Services` | 给主机分配服务 | `<item selected="SSH" v_metric="Count" v_count="4">` | 缺 → 主机只有默认服务 |
| `Routing` 的 `r2s_mode` | 路由器↔交换机聚合策略 | `Exact` = 精确；`r2s_edges` 控每路由挂交换机数 | 影响网段分配 |

### 角色类型（`selected` 合法值，map_role_to_node_type）
`Router` / `Switch` / `Hub` / `Wireless` / 其它 → 默认 PC。
注意 CORE 9.2 协议里**没有独立 ROUTER 节点类型**，路由器是通过「默认 PC 节点 + IPForward/zebra/OSPF 服务」表达的 —— AgentCyTE 在 segmented 路径里自动加。

## 2. 推送场景到 CORE

### 2.1 通过 CLI（直连，最直接）
```bash
cd /opt/agentcyte          # 离线包 venv 部署目录
CORETG_PORT=9090 bash run.sh &          # (起服务, 可选)

# 推拓扑 → 宿主 core-daemon
PYTHONPATH=$PWD/vendor ./.venv/bin/python3 config2scen_core_grpc.py \
  --xml /path/to/scenario.xml \
  --host 127.0.0.1 --port 50051 --verbose
```
成功标志（日志）：
- `CORE session started`
- `[router.plan] ... final=2`（路由计划）、`building segmented topology with routers`（说明走的是真路由器路径）
- `add_link` 链路成功、`start_session()` ok

### 2.2 通过 Web UI（浏览器, API）
- 起服务 → `http://<host>:9090` 登录（`coreadmin`/`coreadmin`）
- 上传 XML（`POST /load_xml`）或编辑器保存（`POST /save_xml_api`）
- 触发运行（`POST /run_cli` 或 `/run_cli_async`）、看报告（`GET /reports`）
- 规划预览（不真实建会话）：`POST /api/plan/preview_full` `{"xml_path": "...", "seed":42}`

## 2.3 通过 AgentCyTE 自身 HTTP API 推送（端到端实测）

> 此链路完整验证过：`login → run_cli_async → run_status → CORE 建会话`，双入口（bridge + 宿主 GetSessions）逐字段一致。

**⚠️ 核心前提（最易踩坑）：必须用 `CORE_PY` 指定 venv 解释器启动服务。**
`run_cli_async` 会另起 CLI 子进程推 topology，解释器由 `webapp/app_backend.py: _select_python_interpreter()` 挑选，优先级：
`CORE_PY` 环境变量 → `core-python` → `python3` → `python` → `sys.executable`。
系统自带的 `/usr/bin/python3` 缺 `google`(protobuf)，只装在 venv 里 → 子进程 `import core.api.grpc` 失败 → 全程走 **offline report-only**（CLI log 出现 `core.api.grpc not available`，不建任何 CORE session）。
**修复：服务启动时显式设 `CORE_PY=$PKG/.venv/bin/python3`**（priority 1）。

### 启动服务（带 CORE_PY）
```bash
PKG=/tmp/agentcyte-offline-verify/agentcyte
CORETG_PORT=9093 CORE_PY=$PKG/.venv/bin/python3 PYTHONPATH=$PKG/vendor \
  nohup $PKG/.venv/bin/python3 main.py > /tmp/agcyte_own_api.log 2>&1 &
ss -ltn | grep 9093                      # 确认监听
tr '\0' '\n' < /proc/<pid>/environ | grep CORE_PY   # 确认 env 生效
```

### 完整 HTTP 流程（curl）
```bash
B=http://127.0.0.1:9093
curl -s $B/healthz                          # ok, 200
curl -s -c /tmp/c -d "username=coreadmin&password=coreadmin" $B/login   # 302 建 cookie
RUN=$(curl -s -b /tmp/c -F "xml_path=$PKG/scenario.xml" \
          -F "host=127.0.0.1" -F "port=50051" $B/run_cli_async)
# {"run_id":"<uuid>"}
for i in $(seq 1 8); do sleep 2; curl -s -b /tmp/c $B/run_status/<run_id>; done
# done=true, returncode=0 → 子进程完成真推送
```

### 确认生效的证据（CLI log `cli-<run_id>.log`）
- `Using python interpreter: .../.venv/bin/python3`（必须，不是 `/usr/bin/python3`）
- `[router.plan] ... final=2`、`building segmented topology with routers`
- `add_node id=1 name=router-1 type=DEFAULT`、`add_link`（真路由器 + 链路）
- `CoreGrpcClient.start_session() ok`、**`CORE session started`**（这才是真建会话）

### 实测结果（20 节点场景）
- **入口 B**：`GET http://127.0.0.1:8080/api/sessions` → `[{"id":1,"state":4,"nodes":20,"dir":"/tmp/pycore.1"}]`
- **入口 A**：宿主原生 `GetSessions` → `session id=1 state=4 nodes=20 dir=/tmp/pycore.1`（**与 B 完全一致**，证明 HTTP API 链路对宿主 CORE 真实生效）
- 节点构成：真路由器 `router-1/2` + 交换机 `rsw-1-1..2-2` + 工作站 `workstation-1-1..2-5`（5 台主机分到 2 路由网段）

### 验证后清理
```bash
curl -s -X DELETE http://127.0.0.1:8080/api/sessions/1   # 删会话
curl -s http://127.0.0.1:8080/api/sessions                # → [] 无残留
ps -eo pid,args | grep 'vcmd.*pycore' || echo no-vcmd      # 无 vcmd 残留
kill -9 <主进程 pid>  # 停服务; 用 pgrep -f main.py 逐个杀,勿用 pkill -f 自身
```

## 3. 双入口确认会话（验证 AgentCyTE 对 CORE 真的生效）

### 入口 A：宿主 CORE 原生（GetSessions）
```bash
/opt/core/venv/bin/python3 -c "
from core.api.grpc.client import CoreGrpcClient
from core.api.grpc import core_pb2
c=CoreGrpcClient('127.0.0.1:50051'); c.connect()
r=c.stub.GetSessions(core_pb2.GetSessionsRequest())
for s in r.sessions: print('session id=%s state=%s nodes=%s' % (s.id, s.state, s.nodes))
c.close()
"
```
> 注意：必须调 `.connect()` 才有 stub（否则 stub=None）。

### 入口 B：core-http-bridge（HTTP）
```bash
curl -s http://127.0.0.1:8080/api/sessions           # 会话清单
curl -s http://127.0.0.1:8080/api/sessions/1          # 会话详情(节点/服务)
curl -s -X DELETE http://127.0.0.1:8080/api/sessions/1  # 删除会话
```
同一会话两个入口看到的状态一致（id / state=4 RUNNING / nodes 数 / dir `/tmp/pycore.N`）。

## 4. 清理会话（避免残留, CLAUDE.md 重点提醒）

```bash
# 方式1: HTTP(bridge)
curl -s -X DELETE http://127.0.0.1:8080/api/sessions/<id>

# 方式2: CORE 原生 CLI
/opt/core/venv/bin/core-cli session -i <id> delete

# 确认无残留
curl -s http://127.0.0.1:8080/api/sessions           # → []
ls /tmp/pycore.* 2>/dev/null || echo clean           # → clean
ps -eo pid,args | grep 'vcmd.*pycore' || echo no-vcmd  # → 无 vcmd 残留
```
> vcmd 进程如不回收会持续 ~28% CPU（详见 CLAUDE.md 坑 #2），用 `kill -9` 清理。

## 5. 常见坑（实测踩过）

1. **section 名写错 → 静默 fallback**：`Basic` + `role count` 写法不认，节点变默认 10 Workstation。必须用 `Node Information` + `<item selected v_metric=v_count>`。
2. **只有 Node Information、没 Routing → router 是假的**：router 节点建成普通 PC（无 zebra/OSPF），拓扑走 star。补 `<section name="Routing">` 才走 segmented、建真路由器。
3. **gRPC stub 为 None**：CoreGrpcClient 需 `.connect()` 后才暴露 stub。
4. **CoreGrpcClient 构造**：传单字符串 `'host:port'`，不要拆成 `(host, port)`（第二个位置是 proxy 标志）。
5. **宿主 core-daemon 必须 50051 在监听**：`ss -ltn | grep 50051`。
6. **core-http-bridge 与宿主 core 状态一致**：两边看到的会话完全相同（同 id/state/nodes/dir）。
7. **`/run_cli_async` 走 offline 不建会话**：`_select_python_interpreter()` 挑了系统 `/usr/bin/python3`（缺 protobuf）→ 子进程 `import core.api.grpc` 失败。**必须 `CORE_PY=$PKG/.venv/bin/python3` 启动服务** 再用 HTTP 触发（详见 2.3）。

## 6. 端到端一次性验证脚本

```bash
PKG=/opt/agentcyte
# 1. 推拓扑
PYTHONPATH=$PKG/vendor $PKG/.venv/bin/python3 $PKG/config2scen_core_grpc.py \
  --xml $PKG/scenario.xml --host 127.0.0.1 --port 50051 | grep -E "CORE session started|session started"
# 2. bridge 确认
curl -s http://127.0.0.1:8080/api/sessions
# 3. 宿主原生确认
/opt/core/venv/bin/python3 -c "
from core.api.grpc.client import CoreGrpcClient; from core.api.grpc import core_pb2
c=CoreGrpcClient('127.0.0.1:50051'); c.connect()
print([ (s.id,s.state,s.nodes) for s in c.stub.GetSessions(core_pb2.GetSessionsRequest()).sessions]); c.close()"
# 4. 清理
SID=$(curl -s http://127.0.0.1:8080/api/sessions | python3 -c "import sys,json;print(json.load(sys.stdin)[0]['id'])")
curl -s -X DELETE http://127.0.0.1:8080/api/sessions/$SID
```
